# Документация Wakelab

Wakelab реализует этап активации по ключевому слову в локальном голосовом
конвейере. Библиотека синхронно принимает непрерывный поток PCM-аудио и возвращает
те же семплы с независимыми признаками `is_speech` и `is_activated`.

## Содержание

1. [Установка](installation.md): поддерживаемые системы, установка из Git,
   зависимости и требования к моделям.
2. [Использование библиотеки](usage.md): создание и полный жизненный цикл
   потокового процессора.
3. [Справочник API](api.md): публичные типы, методы, ошибки, диагностика и
   интерфейсы заменяемых бэкендов.
4. [Модели и артефакты](models.md): Silero VAD, openWakeWord, целостность кеша,
   офлайн-режим и требования к классификатору.
5. [Демо и инструменты](demos.md): пример с микрофоном, профили, диагностический
   стенд и бенчмарк.
6. [Разработка](development.md): устройство репозитория, архитектура, тесты и
   требования к изменениям.

Для программных агентов предназначена отдельная англоязычная
[инструкция по интеграции для LLM](../llm/wakelab.md). Английская документация
начинается в [doc/en/README.md](../en/README.md).

## Область ответственности

Wakelab отвечает за синхронную потоковую обработку, политики VAD и ключевого слова,
состояние активации, адаптеры моделей и метаданные результата. Приложение отвечает
за:

- захват аудио с микрофона или чтение из файла;
- приведение аудио к требуемому формату до вызова Wakelab;
- происхождение, проверку целостности и лицензию классификатора ключевого слова;
- распознавание речи, запись команды, транспорт и состояние ассистента;
- сериализацию доступа из нескольких потоков;
- настройку логирования и повторы при ошибках подготовки моделей.

В Wakelab намеренно нет API микрофона, ресемплера, многоканальной обработки,
PyTorch-исполнения, асинхронного API и внутреннего потока для моделей.

## Основные гарантии

- Каждый принятый семпл возвращается ровно один раз и в исходном порядке.
- Семплы не ресемплируются, не синтезируются, не перекрываются и не изменяются.
- Входные блоки могут иметь любую ненулевую длину; размеры кадров моделей скрыты
  внутри бэкендов.
- Смена поколения и разрыв непрерывности являются жесткими границами состояния
  моделей и временной шкалы.
- Активация сохраняется до вызова `rearm()`.
- После активации инференс ключевого слова не выполняется.
- Загрузка файлов, создание сессий, проверка и прогрев выполняются вне `process()`.
- После терминальной ошибки можно получить все принятое аудио без нового инференса.

Процессор может удерживать аудио до принятия решения, поэтому отдельный вызов
`process()` может вернуть пустой список. Конечный поток необходимо явно завершить,
чтобы получить все принятые семплы.
