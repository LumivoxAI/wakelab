# Разработка

## Подготовка репозитория

Wakelab использует `uv` для окружения, зависимостей и сборки, `just` для сценариев,
Ruff для форматирования и линтинга, строгий mypy и pytest.

```console
git clone https://github.com/LumivoxAI/wakelab.git
cd wakelab
just postclone
just precommit
```

Основные команды:

| Команда | Назначение |
| --- | --- |
| `just sync` | Синхронизировать обычные и dev-зависимости. |
| `just fmt` | Отформатировать репозиторий. |
| `just lint` | Запустить проверки Ruff. |
| `just typecheck` | Запустить строгий mypy. |
| `just test` | Запустить набор тестов по умолчанию. |
| `just lock_check` | Проверить соответствие `uv.lock` метаданным проекта. |
| `just build` | Собрать sdist и wheel без локальных source overrides. |
| `just precommit` | Запустить форматирование, линтинг, типы, тесты и lock check. |

Конфигурация pytest по умолчанию исключает тесты с маркером `model`. Для реальных
тестов openWakeWord также нужен совместимый классификатор в тестовом окружении.

## Архитектура

Production-конвейер:

```text
проверка InputChunk и границ непрерывности
  -> ограниченная временная шкала семплов
  -> фрейминг и инференс вероятности VAD
  -> hysteresis, debounce и padding политики VAD
  -> фрейминг и инференс ключевого слова с учетом VAD
  -> жизненный цикл активации
  -> сегментация и метаданные OutputChunk
```

Адаптеры инференса возвращают вероятности. Временные политики принимают решения о
речи, кандидатах и активации. Только процессор владеет отложенным PCM и определяет,
когда метаданных достаточно для выдачи.

Логические позиции являются счетчиками семплов за все время процессора. Внутренние
и диагностические диапазоны являются полуинтервалами `[start, end)`. Поэтому дрейф
времени и физическое зацикливание буфера не влияют на порядок и сохранность.

## Обязательные инварианты

- Сохранять каждый принятый семпл ровно один раз и в исходном порядке.
- Не переносить кадры моделей через разрывы и смену поколения.
- Хранить признаки VAD и активации независимо.
- Сохранять активацию до явного re-arm.
- Не запускать wake-инференс после активации.
- Не выполнять сетевые операции, загрузку, создание сессий и прогрев в hot path.
- Не выносить размеры кадров и имена тензоров моделей в публичный входной контракт.
- Сохранять обработку синхронной, последовательной и ограниченной по памяти.
- Никогда не импортировать production-код из `src/tmp`.

`src/tmp` содержит временные read-only материалы исследования. Их нельзя изменять,
упаковывать, импортировать или считать API прототипов обязательным для совместимости.

## Тестирование изменений

Предпочитайте детерминированные фальшивые бэкенды и синтетические последовательности
с узнаваемыми семплами. Проверяйте разное разбиение одного аудио на входные блоки.
Выходные диапазоны должны быть упорядочены, не пересекаться, не иметь пропусков и
объединяться в исходный ввод.

Изменения бэкендов требуют тестов детерминированного reset, транзакционной ошибки
инференса, provider, схемы и идемпотентного close. Для артефактов нужны проверки
кеша, повреждения, неверного дайджеста, оборванной загрузки и атомарной публикации без
сети в стандартном наборе тестов.

После изменений запускайте `just precommit`. При изменении публичных экспортов или
структуры пакета также запускайте `just build` и проверяйте артефакты на кеши,
модели, прототипы и неподдерживаемые файлы.

## Правила публичного API

Поддерживаемые имена экспортируются из `lumivox_wakelab`,
`lumivox_wakelab.vad` или `lumivox_wakelab.wakeword`. Модули и имена с начальным
подчеркиванием внутренние и могут меняться без обратной совместимости. Вспомогательный
код профилей и инструменты в `tools/` и `examples/` не являются API пакета.

Пакет получает `lumivox_core.logger.Logger` от приложения и добавляет контекст
Wakelab. Библиотечный код не должен глобально настраивать логирование и не должен
писать обычные события каждого кадра на стандартных уровнях.
