# Демо и инструменты

Команды ниже выполняются из репозитория, подготовленного через `just postclone`.
Это инструменты репозитория, а не API устанавливаемого пакета.

## Запись по ключевому слову

Пример для Linux/PipeWire использует Devicelab, ожидает ключевое слово и записывает
ограниченный активированный фрагмент в WAV: mono, 16 кГц, PCM16.

Получить список устройств без загрузки ONNX-моделей:

```console
uv run python -m examples.microphone_wake_recorder --list-microphones
```

Использовать устройство по умолчанию и записать десять секунд активированного аудио:

```console
uv run python -m examples.microphone_wake_recorder
```

Задать параметры явно:

```console
uv run python -m examples.microphone_wake_recorder \
  --microphone-id 'device-id-from-list' \
  --profile examples/profile.json \
  --output recordings/command.wav \
  --duration 5
```

Каталог назначения должен существовать, а файл назначения не должен существовать.
После Ctrl+C уже собранное активированное аудио сохраняется как частичная запись.

Профиль `examples/profile.json` ожидает приватный локальный классификатор по
указанным в нем пути и дайджесту. Этого файла нет в репозитории. Скопируйте профиль
и укажите свой путь, SHA-256, политики и границу удержания. Относительные пути
вычисляются от файла профиля, а не от текущего каталога shell.

## Диагностический стенд

Запуск локального стенда NiceGUI:

```console
uv run python tools/wake_pipeline_lab.py --profile tools/profile.json
```

Сервер доступен только на `127.0.0.1`. Он показывает ограниченную историю входа,
VAD, score ключевого слова, переходов состояния и очереди диагностики. Изменения
профиля во время прослушивания применяются при следующем Start. Каждый Start создает
и прогревает новые бэкенды.

Стенд предназначен для диагностики и калибровки политики под конкретный
классификатор. Его профиль не является production-настройкой и может отличаться от
профиля микрофонного примера.

## Бенчмарк

Измерение синтетического пути с удержанием аудио:

```console
uv run python tools/benchmark_streaming.py
```

Параметры `--feature-dir`, `--classifier` и `--openwakeword-frames` включают
измерение реального steady-state инференса openWakeWord после прогрева. Полный список
доступен через `uv run python tools/benchmark_streaming.py --help`.

Результаты бенчмарка зависят от оборудования и не являются гарантией задержки.
